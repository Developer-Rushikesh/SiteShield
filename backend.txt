# BACKEND DEVELOPMENT PROMPT

## Django REST API + SQLite + Real Website Monitoring

The React frontend has already been created.

Now build the complete BACKEND and replace the frontend mock data with real Django REST API data.

Do NOT redesign the frontend.

The existing React UI and routes should remain intact unless a small change is required for API integration.

---

# 1. Backend Technology

Use:

* Python
* Django
* Django REST Framework
* SQLite
* Django ORM
* django-cors-headers
* requests or httpx

Do NOT use PostgreSQL yet.

Do NOT require Redis/Celery in the initial implementation.

However, structure the monitoring service so Celery + Redis can be added later.

# 7. Website Monitoring Service

Create a dedicated monitoring service.

Example:

```text
monitors/
    services/
        monitoring_service.py
```

Create:

```text
check_website(monitor)
```

It must:

1. Validate URL
2. Make HTTP/HTTPS request
3. Measure response time
4. Capture HTTP status
5. Determine UP/DOWN/WARNING
6. Save MonitoringRecord
7. Update Monitor
8. Detect incident
9. Resolve incident when recovered
10. Create notifications where necessary

---

# 8. Status Rules

Implement clear rules.

Example:

```text
UP:
HTTP 2xx / 3xx

WARNING:
Slow response

DOWN:
Connection failure
Timeout
DNS failure
HTTP 5xx
```

Handle:

```text
400
401
403
404
429
500
502
503
504
timeout
connection error
DNS error
SSL error
```

Do not blindly classify every HTTP error as infrastructure failure.

Store the actual HTTP status for transparency.

# 14. URL Security

This is VERY important.

Because users provide URLs that the server will request, protect against SSRF.

Do not allow monitoring of:

```text
127.0.0.1
localhost
0.0.0.0
private IPv4 ranges
private IPv6 ranges
cloud metadata endpoints
internal network addresses
```

Validate URLs before monitoring.

Only allow:

```text
http://
https://
```

Do not trust user-provided URLs blindly.

# 22. Scheduler Architecture

For the initial version:

DO NOT put an infinite loop inside Django API requests.

The architecture must keep monitoring logic independent.

Create:

```text
Monitoring Service
```

which can later be executed by:

```text
Celery Worker
```

For this first SQLite version, provide a simple development mechanism for scheduled monitoring and clearly document its limitations.

Also keep:

```text
Check Now
```

working independently.

Future production architecture:

```text
Django
   ↓
Celery
   ↓
Redis
   ↓
Monitoring Worker
   ↓
Website
```
